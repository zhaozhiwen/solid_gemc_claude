## Introduction

GEMC is a wrapper around Geant4 for detector simulation. The architecture
separates geometry, materials, mirrors, and hit processing from the core
code, allowing simulation of any detector without recompiling GEMC.

### How It Works

- **External definitions**: Geometry, material, mirror, and hit processing
  are defined externally in delimiter-separated values format, stored in
  text files or databases, and generated by Perl scripts.
- **Parameters**: Detector parameters use delimiter-separated values
  format, editable by hand or stored in databases.
- **Hit processing routines**: Defined in source code, compiled with GEMC
  as a library.

## Breaking Changes

### GEMC 2.3 to GEMC 2.9

GEMC 2.3 is in jlabce 1.3; GEMC 2.9 is in jlabce 2.5.

Changes:

- Optical photon PDG encoding changed from 0 to -22 with Geant4.10.7.
- Option required: `RECORD_OPTICALPHOTONS=1` to enable optical physics
  alongside `PHYSICS="QGSP_BERT+STD+Optical"`.
- Field options required:
  `FIELD_PROPERTIES="oxford_ptarget, 1*mm, G4ClassicalRK4,linear"` and
  `DISPLACE_FIELDMAP="oxford_ptarget,0*cm,0*cm,-350*cm"` for all global
  and local field maps.

Reference: <https://github.com/gemc/source/issues/231>

### Converting GEMC 1 to GEMC 2 Format

1. Update header due to IO engine changes.
2. Add `my %detector=init_det();`.
3. Replace `print_det(\%detector, $file);` with
   `print_det(\%configuration, \%detector);`.
4. Replace empty `""` entries with `"no"`.
5. Use lowercase `"flux"` only (not `"FLUX"`).
6. Add `*counts` suffix for pure numbers in `"dimensions"`.

## Building Simulation

### Introduction and Format

Building a simulation involves creating the experiment setup by defining:

- Geometry with material or mirror properties.
- Sensitive geometries with hit processing.
- All defined in table format with fixed entries.

Files can be stored as text files or in a database. GEMC uses Perl tools
to generate text files, which can also be edited manually. Only the hit
process routine is C++ code, compiled and linked to GEMC.

### Perl Module Location

Perl modules for generating text files are located at `$GEMC/io` (older
versions) or `$GEMC/api/perl` (newer versions).

Ensure compatibility:

```perl
use lib ("$ENV{GEMC}/io");
use lib ("$ENV{GEMC}/api/perl");
```

### Parameters

Example:
<https://jlabsvn.jlab.org/svnroot/solid/solid_gemc2/geometry/ec_segmented/solid_PVDIS_ec_forwardangle__parameters_Original.txt>

No general Perl script generates parameters; edit by hand. In geometry
scripts, use:

```perl
our %parameters = get_parameters(%configuration);
```

This allows parameters to be called and used in geometry definition
scripts.

### Geometry

#### Define in Text Format

| Entry | Description |
|-------|-------------|
| name | Volume name |
| mother | Parent volume name or `root` for world |
| description | Volume description (no simulation impact) |
| pos | Position relative to mother (x y z) |
| rotation | Rotation relative to mother along x y z axes |
| color | HEX color code |
| Type | Geant4 solid shape name |
| dimensions | Geant4 solid dimensions |
| material | Geant4, GEMC built-in, or customized material |
| mfield | Local magnetic field filename (applies to volume only) |
| ncopy | Copy number |
| pMany | 0 or false (not used by Geant4 at `G4PVPlacement`) |
| exist | 1 or 0 (active in simulation or not) |
| visible | 1 or 0 (display in graphic mode or not) |
| style | 1 or 0 (solid or wireframe display) |
| sensitivity | `no` or other string (marks if sensitive) |
| hit_type | Hit type name (if sensitive) |
| identifiers | Identifier string (if sensitive) |

**Example**

```
meic_det1_rich_detector_holder | root | meic_det1_rich_detector_holder | 0*mm 0*mm 0*mm | 0*deg 0*deg 0*deg | ffffff | Box | 56.25*mm 56.25*mm 12*mm | Air_Opt | no | 1 | 1 | 1 | 1 | 0 | no | no | no
```

Tutorial:
<https://gemc.jlab.org/gemc/html/documentation/detectorDefinition.html>

Source: <https://github.com/gemc/source/blob/master/detector/detector.cc>

#### Mother, Position, Rotation

- The `root` volume is a large box with customizable size at runtime.
- Position is relative to the mother volume.
- Rotation angles are defined by rotating the mother frame (add minus
  sign when rotating daughter).
- Rotation angles can be ordered; double rotation is supported.
- Rotation axis is in the daughter's local frame.

Reference: <https://github.com/gemc/source/blob/master/utilities/gemcUtils.cc>

#### Type and Dimensions

**Geant4 Solids**

GEMC accepts all Geant4 solid shapes and dimensions:
<https://geant4-userdoc.web.cern.ch/geant4-userdoc/UsersGuides/ForApplicationDeveloper/html/Detector/Geometry/geomSolids.html>

Name and dimension parsing:
<https://github.com/gemc/source/blob/main/detector/detector.cc>

**Polycone (PCON)**

Standard Geant4:

```cpp
G4double StartPhi=0;
G4double DeltaPhi=360;
G4double poly_z[2] = {0*mm, 1.*mm};
G4double poly_rmin[2] = {40.0*mm, 40.0*mm};
G4double poly_rmax[2] = {50.0*mm, 40.001*mm};
G4Polycone *solidGroove1 = new G4Polycone("Groove1",StartPhi,DeltaPhi, 2, poly_z, poly_rmin, poly_rmax);
```

GEMC Perl format:

```perl
$detector{"type"}       = "Polycone";
$detector{"dimensions"} = "0*deg 360*deg 2*counts 40*mm 40*mm 50*mm 40.001*mm 0*mm 1*mm";
```

**Polyhedra (PGON)**

Standard Geant4:

```cpp
G4double StartPhi=0;
G4double DeltaPhi=360;
G4double poly_z[2] = {0*mm, 1.*mm};
G4double poly_rmin[2] = {40.0*mm, 40.0*mm};
G4double poly_rmax[2] = {50.0*mm, 40.001*mm};
G4Polyhedra *solidGroove1 = new G4Polyhedra("Groove1",StartPhi,DeltaPhi,6, 2, poly_z, poly_rmin, poly_rmax);
```

GEMC Perl format:

```perl
$detector{"type"}       = "Pgon";
$detector{"dimensions"} = "0*deg 360*deg 6*counts 2*counts 40*mm 40*mm 50*mm 40.001*mm 0*mm 1*mm";
```

**Boolean Operations**

For union / subtraction / intersection:

1. Use `operation: volumeA + VolumeB`, `operation: volumeA - VolumeB`, or
   `operation: volumeA * VolumeB`.
2. Use `operation:@ ...` where `@` means position of second object is
   given in the common mother volume.
3. Define volumes A and B with material `Component` so they won't be
   built separately.
4. Example:
   <https://phys12svn.jlab.org/repos/gemc/systems/clas12/htcc/geo/mirrors.pl>

**Volume Copy**

1. Use `CopyOf volumeA` in the type field.
2. Examples:
   - <https://phys12svn.jlab.org/repos/gemc/systems/clas12/ft/geometry.pl>
   - <https://jlabsvn.jlab.org/svnroot/solid/subsystem/ec/ec_segmented_solid_gemc/solid_PVDIS_ec_forwardangle_geometry.pl>

#### Link Material

**Geant4 Materials**

All Geant4 material names can be used directly:
<https://geant4-userdoc.web.cern.ch/UsersGuides/ForApplicationDeveloper/html/Appendix/materialNames.html>

**Empty Material Field**

Empty material (`""`) can be filled at runtime with option:
`DEFAULT_MATERIAL`.

**Hall Material (root)**

Set at runtime with option `HALL_MATERIAL`:

- `Air` — normal simulation
- `Air_Opt` — simulation with optical physics (default)
- `Vacuum`

**Total Absorber**

`Kryptonite` kills any track touching it. Ends the track in step action.
Implemented as very-low-density material in `material.cc`, making
secondaries from the primary particle almost impossible. Note:
Kryptonite hits can occur at detector front or back on the track path;
use `mpid` in true info to veto secondaries.

**Customized Materials**

Defined separately (see Material section below).

#### Link Local Magnetic Field

Local magnetic field is defined by the `mfield` entry and uses the same
field-map file format as the global field (defined in option
`HALL_FIELD`).

- Local field lives within the geometry or its field map, whichever is
  smaller.
- All daughter geometries inherit the mother's field.
- When local and global fields overlap, local field wins.

#### Link Sensitivity

**Non-sensitive Geometry**

```perl
$detector{"sensitivity"} = "no";
$detector{"hit_type"}    = "no";
$detector{"identifiers"} = "no";
```

**Sensitive with Built-in `flux` Hit Processing**

```perl
$detector{"sensitivity"} = "flux";
$detector{"hit_type"}    = "flux";
$detector{"identifiers"} = "id manual 1";
```

**Sensitive with Customized Hit Processing (e.g., `wire`)**

```perl
$detector{"sensitivity"} = "wire";
$detector{"hit_type"}    = "wire";
$detector{"identifiers"} = "sector ncopy 0 stack manual 3 view manual 6 strip manual 36";
```

**Important:** Identifiers must be unique for each geometry; otherwise,
hits average over different geometries producing non-physical results.

Identifier format example breakdown:

- `sector ncopy 0` — number filled at runtime
- `stack manual 3` — explicit number
- `view manual 6` — explicit number
- `strip manual 36` — explicit number

#### Link Mirror

```perl
$detector{"sensitivity"} = "mirror: SL_HGC_mirror";
$detector{"hit_type"}    = "mirror";
```

### Load from GDML and CAD Files

GDML and CAD files in mesh format can be loaded directly. Reference:
<https://gemc.jlab.org/gemc/html/documentation/gdmlCadFactories.html>

**Important notes**

1. CAD files can significantly slow simulation.
2. Add `/` after directory names; GEMC loads all CAD files in the
   directory.
3. `cad.gxml` is required, otherwise GEMC will quit.
4. Use names like `name="solid_layout7_steel_v4"` without file extension.
5. Use `hitType` instead of `hit_type` in CAD geometry definitions.

### Check Overlap

Volume overlap causes GEMC to crash after beam starts. Check with option
`CHECK_OVERLAPS`:

- `1` — check overlaps at construction time
- `2` — check overlaps based on standard lines grid setup
- `3` — check overlaps by shooting lines in cylindrical pattern

**Note:** Overlap checking only works in batch mode (`USE_GUI=0`), not
in graphic mode.

**Envelope Volumes**

To enclose geometry (e.g., EC volume with vacuum), set mother volume
to `root`. Envelope volume overlaps won't cause crashes if non-sensitive,
but GEMC tracking will fail if sensitive volumes overlap. Avoid all
overlaps.

## Hit Processing

### Introduction

First understand GEMC hits:

- <https://gemc.jlab.org/gemc/html/documentation/hitDefinition.html>
- <https://github.com/gemc/source/blob/main/sensitivity/sensitiveDetector.cc>

Hit processing requires three coordinated components:

1. **Hit definition** — provides runtime control to fine-tune hit
   processing.
2. **Bank definition** — specifies what information to store and exact
   output entries.
3. **Hit process routine** — performs actual processing to fill banks
   per hit definition.

Built-in `flux` type is hardcoded in GEMC and cannot be modified.
Customized hit processing requires all three components with matching
names across definitions and geometry specifications.

Linking happens through a unique hit processing name (e.g., `solid_hgc`
or `eic_ec`) used in all three places.

### Hit Definition

#### Built-in Type

Built-in `flux` type parameters:

- `signalThreshold = 0`
- `timeWindow = 0`
- `prodThreshold = 1*mm` (GEMC ≥ 2.3) or `0.001*mm` (GEMC < 2.3)
- `maxStep = 1*mm`

The `timeWindow` of 0 sums all steps within a sensitive volume with the
same ID from one track into a single hit. This fails when a track passes
through a detector more than once (e.g., low-energy charged particle
bent backward by magnetic field), averaging multiple hits and producing
non-physical results.

All built-in types:
<https://github.com/gemc/source/blob/master/sensitivity/sensitiveID.cc>

#### Customized Type

A `*_hit.pl` script produces a text file `*__hit_*.txt` with entries
like:

```perl
$hit{"name"}            = "solid_hgc";
$hit{"description"}     = "solid hgc hit definition";
$hit{"identifiers"}     = "id";
$hit{"signalThreshold"} = "0.*MeV";
$hit{"timeWindow"}      = "0*ns";
$hit{"prodThreshold"}   = "1*mm";
$hit{"maxStep"}         = "1*mm";
$hit{"delay"}           = "10*ns";
$hit{"riseTime"}        = "1*ns";
$hit{"fallTime"}        = "1*ns";
$hit{"mvToMeV"}         = 100;
$hit{"pedestal"}        = -20;
```

**Entry meanings**

- `name` — same name as bank definition and hit-process routine.
- `identifiers` — format distinguishing detector components
  (e.g., `sector stack view strip`).
- `signalThreshold` — minimum energy cut for particle display only.
- `timeWindow` — matches ADC/TDC integration window. Within window, all
  hits in one detector component combine into one. `0*ns` treats every
  individual hit separately (slower processing).
- `prodThreshold` — energy threshold below which tracks don't continue;
  all energy deposits in current volume. Too large produces too few
  tracks (non-physical). Originally energy units in Geant4, now uses
  length units for material independence. Geant4 default is 1 mm
  globally; GEMC allows per-hit-type configuration. References:
  <https://geant4.web.cern.ch/geant4/UserDocumentation/UsersGuides/ForApplicationDeveloper/html/ch05s04.html>,
  <https://geant4.web.cern.ch/geant4/UserDocumentation/UsersGuides/ForApplicationDeveloper/html/ch05s05.html>,
  <http://geant4.slac.stanford.edu/JLAB2012/Physics3.pdf>.
- `maxStep` — Geant4 calculates step size per material; can be too large
  for gases requiring more steps (e.g., drift chambers). GEMC uses the
  smaller of this value and Geant4's suggestion. **Cannot be 0** (causes
  memory overflow).
- `delay` — electronic delay.
- `riseTime` — signal rise time.
- `fallTime` — signal fall time.
- `mvToMeV` — conversion factor.
- `pedestal` — baseline offset.

### Bank Definition

#### Built-in Type

Built-in `flux` type records:

- `hitn` — number of hits on sensitive detector
- `id` — integer identifying the detector

`mirror` records photon hits on mirrors.

All built-in types:
<https://github.com/gemc/source/blob/master/output/gbank.cc>

#### Customized Type

A `*_bank.pl` script produces a text file `*__hit_*.txt` with entries
similar to:

```perl
$bank{"name"}        = "solid_hgc";
$bank{"description"} = "solid hgc hits";
$bank{"bankid"}      = 1320;
$bank{"hitn"}        = 0;
```

**Requirements**

- At least three unique entries: `bankid`, `hitn` (hit count), and
  identifier.
- Identifier format customizable (e.g., `sector manual 1 layer manual 2`)
  matching hit definition and hit-process routine.
- Additional entries can be defined and filled in hit-process routine.
- **Additional entries cannot have same names as "true info" entries**,
  preventing conflicts when "true info" is recorded.

#### True Info

`True info` records particles in sensitive volumes. Disabled by default.

Enable with options like:

```xml
<option name="INTEGRATEDRAW" value="flux,solid_gem"/>
```

This adds additional entries (see
<https://gemc.jlab.org/gemc/html/documentation/hitDefinition.html>) to
bank output.

**Process Names / ID Table:** Changes between versions. Check your
version in `source/sensitivity/sensitiveDetector.cc` and search for
`procName`. Latest:
<https://github.com/gemc/source/blob/master/sensitivity/sensitiveDetector.cc>

### Hit Process Routine

#### Built-in Type

<https://github.com/gemc/source/tree/master/hitprocess>

#### Customized Type

**Important:** All quantities use `MeV,mm,ns` units (Geant4 defaults).

## Generating Experiment Setup

Once all components are defined (parameters, geometry, material, mirror,
bank, hit), generate the experiment setup:

```bash
./solid_PVDIS_ec_forwardangle.pl config_solid_PVDIS_ec_forwardangle.dat
```

The Perl script:

1. Sets up environment variables.
2. Calls all other Perl scripts.
3. Generates a series of text files.
4. Optionally loads them into a database.

Configuration file specifies detector name and storage method (text or
database).

## Field

- **Global Field** — set by option `HALL_FIELD`.
- **Local Field** — defined in individual volume definitions, living
  within the geometry or its field map (whichever is smaller). All
  daughter geometries inherit the mother's field.
- **Field Precedence** — when local and global fields overlap, local
  field wins (daughter field supersedes mother field, as in Geant4).
- **Field Map Loading** — both global and local fields look for `.dat`
  extension files at location defined by `FIELD_DIR`.
- **Field Map Format** — text format supported. Binary field maps also
  supported (faster loading; uncertain about memory use and event
  processing speed).
- **Field Options** — `SCALE_FIELD`, `ROTATE_FIELDMAP`, `FIELD_PROPERTIES`,
  `DISPLACE_FIELDMAP`, `NO_FIELD`.

## Some Special Options

**Include detector with multiple files**

```xml
<detector name="detector_name" factory="TEXT" variation="Original"/>
```

**Turn off volume at runtime**

```xml
<detector name="volume_name">
  <existence exist="no" />
</detector>
```

**Physics lists**

```xml
<option name="PHYSICS" value="QGSP_BERT_HP+HP+STD+Optical"/>
```

- `*_HP` for inelastic hadrons with neutrons below 20 MeV down to thermal
  energies.
- `HP` for elastic hadrons.

**Batch mode**

```xml
<option name="USE_GUI" value="0"/>
```

**Record hits with no energy deposition**

```xml
<option name="RECORD_PASSBY" value="1"/>
```

**Save all mother particle info**

```xml
<option name="SAVE_ALL_MOTHERS" value="1"/>
```

(May slow down processing.)

**Enable true info output**

```xml
<option name="INTEGRATEDRAW" value="flux"/>
```

**Enable step-by-step output**

```xml
<option name="ALLRAWS" value="flux,ec"/>
```

**Physics production cut**

```xml
<option name="PRODUCTIONCUT" value="1"/>
```

Default 10 mm for gamma, e-, e+, p in all volumes. Reference:
<https://github.com/gemc/source/blob/main/physics/PhysicsList.cc>.

**Production cut for specific volumes**

```xml
<option name="PRODUCTIONCUTFORVOLUMES" value="outerMount, 50"/>
```

Same as `prodThreshold` for sensitive volumes; can override for
sensitive volumes. Reference:
<https://github.com/gemc/source/blob/main/src/MDetectorConstruction.cc>.

**Maximum field step**

```xml
<option name="MAX_FIELD_STEP" value="1"/>
```

Sets maximum acceptable step in magnetic field (mm). Applies to all
volumes, significantly affects speed. Default is dynamic per Geant4
density. Impacts low-energy charged particles more than high-energy.
Alternative: add or break large gas volumes into smaller ones (CLAS12
method near beamline).

## Input Format and Passing Information into Output

GEMC accepts two input types. Information passes from input to output
in:

- GEMC < 2.6: `header` and `generated` banks.
- GEMC ≥ 2.6: `header`, `generated`, and `userHeader` banks.

Reference:
<https://github.com/gemc/source/blob/master/output/evio_output.cc>.

### Input Type 1: Particle Guns from Options

**Single particle gun**

```xml
<option name="BEAM_P"   value="e-, 5*GeV, 0*deg, 0*deg"/>
<option name="SPREAD_P" value="0*GeV,0*deg,0*deg"/>
<option name="BEAM_V"   value="(0, 0, 0)m"/>
<option name="SPREAD_V" value="(0.,0)cm"/>
```


**LUND format**

Fully customizable header. Reference:
<https://gemc.jlab.org/gemc/html/documentation/generator/lund.html>.

Particle lines follow webpage definition. Header customizable (10
entries before GEMC 2.3, more after 2.6).

### GEMC < 2.6 Output Banks

- `generated` bank entries: `pid`, `px`, `py`, `pz`, `vx`, `vy`, `vz`
  (units: MeV, mm).
- `header` bank entries: `time`, `runNo`, `evn`, `evn_type`, `var1`,
  `var2`, `var3`, `beamPol`, `var4`, `var5`, `var6`, `var7`, `var8`.
  - `evn` — event number.
  - `evn_type` — −1 for simulation.
  - `beamPol` — beam polarization (default 0).
  - Other variables — 0 from particle gun or from LUND header line.

### GEMC ≥ 2.6 Output Banks

- `generated` bank — added `time` and `multiplicity` entries to previous
  version.
- `header` bank — `time`, `runNo`, `evn`, `evn_type`, `beamPol`.
- `userHeader` bank — `userVar001`, `userVar002`, `userVar003`, …,
  `userVar010`, …. Populated from LUND header entries
  (`Number of particles, userVar002, userVar003, …`). GEMC auto-matches
  entries to output.

## Output

**Direct output formats:** `txt` or `EVIO` (JLab DAQ data format).

Use text output for debugging.

**Convert EVIO to XML**

```bash
evio2xml output.evio
```

**Convert EVIO to ROOT**

Built-in flux bank only:

```bash
evio2root -INPUTF=output.evio
```

Customized bank:

```bash
evio2root -INPUTF=output.evio -B="dir1/bank1 dir2/bank2 ..."
```

Looks for files `dir1/bank1__bank.txt`, `dir2/bank2__bank.txt`, etc.

**Write options**

```bash
-WRITE_RAWS="no"
```

Use if EVIO produced with `ALLRAWS` enabled. Default is `yes`.

**Help**

```bash
evio2root -help-all
```

## Display Shortcuts

### Mouse Shortcuts

- Click and move: rotate volume.
- ALT + click and move: rotate volume (toggle View/Theta-Phi direction).
- CTRL + click and move: zoom in/out.
- SHIFT + click and move: change camera point of view.

### Movement Shortcuts

- Left/right arrows: move volume left/right.
- Up/down arrows: move volume up/down.
- `+` / `-`: move volume toward/forward.

### Rotation (Theta/Phi) Shortcuts

- SHIFT + left/right arrows: rotate volume left/right.
- SHIFT + up/down arrows: rotate volume up/down.

### Rotation (View Direction) Shortcuts

- ALT + left/right: rotate volume around vertical direction.
- ALT + up/down: rotate volume around horizontal direction.

### Zoom View

- CTRL + `+` / `-`: zoom into volume.

### Miscellaneous

- ALT + `+` / `-`: slow/speed rotation/move.
- `H`: reset view.
- Esc: exit fullscreen.

### Video Mode

- SPACE: start/pause video recording.
- RETURN: stop video recording.

## PDF File

**Paid method:** Acrobat (paid version).

**Free method:** Meshlab + pdflatex with U3D embedding.

**Process**

1. Open WRL file in Meshlab on Windows.
2. Export U3D file with "color" selected.
3. Edit generated `.tex` file to add landscape geometry:

   ```
   \usepackage[a4paper,landscape,top=0mm, bottom=0mm, left=0mm, right=0mm]{geometry}
   ```

4. Change `{\linewidth}{\linewidth}` to `{297mm}{210mm}`.

**Final `.tex` structure**

```latex
\documentclass[a4paper]{article}
\usepackage[3D]{movie15}
\usepackage[a4paper,landscape,top=0mm, bottom=0mm, left=0mm, right=0mm]{geometry}
\usepackage{hyperref}
\usepackage[UKenglish]{babel}
\begin{document}
\includemovie[
	poster,
	toolbar,
	label=det1beamline20160316.u3d,
	text=(det1beamline20160316.u3d),
	3Daac=60.000000, 3Droll=0.000000, 3Dc2c=-641.099976 -86745.000000 320.000000, 3Droo=86747.960938, 3Dcoo=-641.114990 5064.898438 -319.960022,
	3Dlights=CAD,
]{297mm}{210mm}{det1_beamline_20160316.u3d}
\end{document}
```

5. Run `pdflatex` with `.tex` and `.u3d` files.
6. View PDF in latest Acrobat Reader.
7. Choose to trust file for 3D content.
8. Rotate, zoom, cut, shed light on 3D object.

**Notes**

- `movie15` and other packages handle U3D in `pdflatex`.
- MiKTeX on Windows requires default installation; `movie15` and
  packages install at runtime.
- Verified with Meshlab 1.3.3 (<http://meshlab.sourceforge.net>) and
  MiKTeX 2.9 (<http://miktex.org/>) on 2016/02.
